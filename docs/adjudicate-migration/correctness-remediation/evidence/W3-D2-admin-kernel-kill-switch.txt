Endpoint surface
================
POST /api/admin/kernel/kill-switch
  Step 1 body: { action: "enable" | "disable", reason: "<text>" }
              → 202 + { confirmationId, prompt, ttlSeconds, action }
  Step 2 body: { action: "confirm", confirmationId }
              → 200 + { active, reason, enabledBy, enabledAt }
              → 410 if receipt unknown / expired / already used
              → 403 if same staff confirms own step 1
              → 403 if either side lacks a staffId (API key path)

GET /api/admin/kernel/kill-switch
              → 200 + { active: true|false, reason?, enabledBy?, enabledAt? }


Auth + governance
=================
- requireManagerRole gate (W4 P1-H — MANAGER or OWNER required,
  fail-closed for API keys without a registry role).
- Two-person rule via constant-time staffId compare. Same staff →
  403 with pt-BR "Outro operador precisa confirmar" message.
- Receipt: random UUID, 10-min TTL, atomic GET+DEL Lua so replay
  cannot succeed even under concurrent step-2 calls.
