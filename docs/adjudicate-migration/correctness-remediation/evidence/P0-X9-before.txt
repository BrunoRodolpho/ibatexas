NEW-P0-X9 — Bypass-detection main scan IS line-based (BEFORE)
===============================================================

Source: deep-audit/07-test-quality.md (verified empirically)
Location: apps/api/src/__tests__/bypass-detection/bypass-detection.test.ts:197-200

Symptom
-------
The main `scan()` function read each file as a string, then split on
"\n" and applied each pattern PER LINE:

    const lines = content.split("\n")
    lines.forEach((text, i) => {
      if (isCommentLine(text)) return
      for (const pattern of patterns) {
        if (pattern.test(text)) { ... }
      }
    })

The FORBIDDEN_MEDUSA patterns (line 128-131) were single-line:

    /medusaStore\([^)]*['"](POST|PUT|DELETE|PATCH)\b/
    /medusaAdmin\([^)]*['"](POST|PUT|DELETE|PATCH)\b/

These required the `method: "POST"` literal to be on the SAME LINE as
the `medusaStore(` call. The common pattern (object-literal options on
later lines) slipped through.

W3 claimed a multi-line upgrade — applied only to the small
`ALLOWED_MEDUSA_DIRECT` carve-out audit (line 297+), not the main scan.
