What the new implementation does
================================

For each audit row in the requested window:
  1. Read the envelope from `record.envelope` (already deserialized
     by `readAuditWindow` from `@adjudicate/audit-postgres`).
  2. Look up the installed Pack for that intent kind via
     `loadPackIndex()` which dynamically imports each first-party
     pack (orders / reservations / whatsapp / customer-onboarding /
     payments / adjudicate-pack-payments-pix) and indexes their
     intent lists.
  3. Call `adjudicate(envelope, {}, pack.policy)` to re-produce the
     CURRENT decision under the current policy bundle.
  4. Classify the drift vs. the historical decision:
       - DECISION_KIND  : new kind ≠ historical kind
       - BASIS          : same kind, different basis category:code set
       - PAYLOAD (REWRITE): same kind, both REWRITE, but
                            `rewritten` envelope differs
  5. Accumulate per-kind counts + totals.

The empty-state {} is intentional — we cannot reconstruct the
historical projection at replay time without a point-in-time DB
read, so we adjudicate against the policy's state-free guards.
Operators read the divergence summary against the runbook's
threshold list, not as an absolute correctness signal.
