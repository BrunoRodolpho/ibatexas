NEW-P0-X8 — Empty-string customerId guard (AFTER FIX)
======================================================

Fix summary
-----------
1. `apps/api/src/middleware/auth.ts` — `extractAuth` no longer assigns
   `request.customerId = payload.sub` if `sub` is `""` or non-string.
   Both customer and staff paths now skip the assignment, leaving the
   request unauthenticated.

   `requireAuth` now uses an explicit `!request.customerId ||
   request.customerId === ""` check and replies with 401 +
   "Sessão inválida." (pt-BR).

2. `apps/api/src/routes/me/anonymize-otp-gate.ts` — adds an
   `assertCustomerId()` helper that throws `InvalidCustomerIdError`
   when `customerId` is null/undefined/non-string/empty. Every Redis-
   key builder (`markOtpFresh`, `hasFreshOtp`, `consumeOtpMarker`,
   `markOtpVerified`, `hasFreshVerifiedOtp`, `consumeOtpVerifiedMarker`,
   `incrementOtpFailureCount`, `getOtpFailureCount`,
   `resetOtpFailureCount`, `setCancelCooldown`, `hasCancelCooldown`,
   `persistPendingDeletion`, `readPendingDeletion`,
   `clearPendingDeletion`) calls `assertCustomerId(customerId)` BEFORE
   touching Redis.
