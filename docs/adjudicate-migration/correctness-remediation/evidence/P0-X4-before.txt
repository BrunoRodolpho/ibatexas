NEW-P0-X4 — PATCH /api/orders/:id/payment/method bypasses kernel (BEFORE)
==========================================================================

Source: deep-audit/02-remediation-verification.md
Location: apps/api/src/routes/order-actions.ts:1020-1095

Symptom
-------
The route chained THREE kernel bypasses inside a single `withLock`:

  1. `paymentCmdSvc.transitionStatus(currentPayment.id, { newStatus: SWITCHING_METHOD, ... })`
  2. `paymentCmdSvc.transitionStatus(currentPayment.id, { newStatus: CANCELED, ... })`
  3. `paymentCmdSvc.create({ orderId, method: newMethod, amountInCentavos })`

Each call invoked the bare-arg (`@deprecated`) entry point on the
command service, completely skipping kernel adjudication:
  - No `withAdjudicate`
  - No audit record
  - No policy gate
  - No state-guard / taint-guard / business-guard ladder

The `payment.method.switch` intent kind was registered in
`@ibatexas/pack-payments` (W5):
  - types.ts:96 declares the kind
  - policies.ts:166 has `validateMethodSwitch` guard
  - policies.ts:442 lists it under `executeAll`
  - capabilities.ts:62 maps it to the LLM-facing `switch_payment_method` tool
  - taint policy: UNTRUSTED (customer-initiated)
But no route ever built or dispatched a `payment.method.switch` envelope.

Pre-fix code (apps/api/src/routes/order-actions.ts:1046-1082):
--------------------------------------------------------------
