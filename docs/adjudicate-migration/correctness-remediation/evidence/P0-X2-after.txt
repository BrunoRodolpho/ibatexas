NEW-P0-X2 — runCustomerIntent default-REFUSE (AFTER FIX)
=========================================================

Fix summary
-----------
1. `apps/api/src/routes/__shared__/customer-intent-gateway.ts` — the
   pure-legacy branch now constructs a REFUSE decision (default-deny)
   with pt-BR userFacing copy:

       decision = {
         kind: "REFUSE",
         refusal: {
           kind: "BUSINESS_RULE",
           code: "customer_intent.kernel_not_configured",
           userFacing:
             "Operação indisponível no momento. Tente novamente em instantes ou entre em contato com o suporte.",
         },
         basis: [],
       };

   `isPureLegacy` is now `false` so the audit emit IS preserved (on-call
   sees the default-deny in telemetry instead of silently EXECUTEing).

2. `ALWAYS_ENFORCE` expanded to cover the safety-critical customer.*
   kinds per the audit's recommendation:

       const ALWAYS_ENFORCE = new Set([
         "customer.anonymize",
         "customer.anonymize.cancel",
         "customer.profile.update",        // NEW
         "customer.preferences.update",    // NEW
         "customer.pix.details.save",      // NEW
       ]);

   `customer.address.*` kinds are intentionally NOT in ALWAYS_ENFORCE
   per audit guidance — pack policy doesn't exist yet, so forcing
   adjudication would default-REFUSE legitimate calls. Routes touching
   address kinds must land them on shadow once policies arrive.

Existing tests updated (these were locking-in the buggy default):
  - apps/api/src/__tests__/order-cancel-governance.test.ts: now asserts
    statusCode 403 (REFUSE) for pure-legacy mode.
  - apps/api/src/routes/__tests__/customer-mutation-governance.test.ts:
    same test flip — pure-legacy now means 403 + executor NOT called.
  - apps/api/src/__tests__/cart-routes.test.ts: SEC-001 checkout tests
    now opt into IBX_KERNEL_SHADOW=order.checkout.create so the legacy
    EXECUTE path is exercised by the cart-checkout test surface.

Caveat
------
This change is high-blast: every legacy customer-mutation kind that ops
hasn't yet listed in shadow/enforce now returns 403 by default. The
rollout playbook (docs/ops/runbooks/) must list ALL active customer
intent kinds and add each to IBX_KERNEL_SHADOW or IBX_KERNEL_ENFORCE
before the next deploy. Default-deny is now structural, not
conditional on operator action.
