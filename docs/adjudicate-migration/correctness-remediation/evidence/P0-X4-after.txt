Fix summary
-----------
apps/api/src/routes/order-actions.ts:1045-1175 (approx.) — the route
now dispatches every mutation through `*FromEnvelope`:

  1. Cancel-old via `transitionStatusFromEnvelope` (kind=payment.status.transition,
     taint=TRUSTED, actor=user/customerId). Possibly 2× when the
     `switching_method` intermediate transition is allowed.
  2. Create-new via `createFromEnvelope` (kind=payment.create,
     taint=SYSTEM, actor=system/customer:{id}).
  3. `withLock` preserved so the cancel→create sequence is atomic per
     payment id.
  4. publishNatsEvent("payment.method_changed", …) runs only after a
     successful EXECUTE/REWRITE on the create envelope.

Decision branching inside the executor:
  - EXECUTE / REWRITE → proceed
  - REFUSE on cancel → tolerated (already terminal)
  - REFUSE on create → returns { refused, userFacing } → 403 + pt-BR
  - Anything else on either → returns { needsEscalation } → 503

This route is NOT routed through customer-intent-gateway because
payment kinds dispatch directly to the payments command service —
same pattern as payment-retry (W3 P0-2) and regenerate-pix.
