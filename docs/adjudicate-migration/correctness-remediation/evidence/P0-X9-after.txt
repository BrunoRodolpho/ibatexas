NEW-P0-X9 — Multi-line bypass-detection (AFTER FIX)
====================================================

Fix summary
-----------

1. New `scanMultiLine()` helper in
   `apps/api/src/__tests__/bypass-detection/bypass-detection.test.ts`:
   reads each file as a single string, strips comments (replacing
   line/block comments with same-length space to preserve line
   numbers), then applies `g`-flag regex via `matchAll`. For each match,
   reports the file:line where the match STARTS.

2. New `FORBIDDEN_MEDUSA_MULTILINE` regex shapes that bound the search
   to a single options-object literal:

       medusaXxx\s*\(            — call open paren
       [^()]*?                   — no nested function calls in args
       \{[^{}]*?                 — opening brace, no nested braces
       \bmethod\s*:\s*['"](POST|PUT|DELETE|PATCH)['"]

   This prevents the lazy `[^]*?` accidentally pairing a GET call's
   opening paren with a LATER unrelated POST call's `method:` literal.

3. The main `Scenario 2` test now uses `scanMultiLine` against the new
   pattern. The original single-line backup test is retained as
   defence-in-depth.

4. New fixture-based unit test:
   `apps/api/src/__tests__/bypass-detection/fixtures/multi-line-bypass.txt`
   contains 4 multi-line bypass variants. The scan MUST detect all 4
   (asserted via `matchAll` against the fixture content).

   Companion test "PRE-FIX REPRODUCTION" verifies that the OLD pattern
   misses 0 of 4 (i.e. catches none), demonstrating the gap.

5. `DEFERRED_MEDUSA_MIGRATIONS` allow-list (3 files, 13 sites):
     - apps/api/src/routes/admin/products.ts
     - apps/api/src/routes/cart.ts
     - apps/api/src/routes/stripe-webhook.ts

   These are PRE-EXISTING bypasses surfaced by enabling the multi-line
   scan. Migrating them is out of scope for cluster B; tracked as a
   follow-up task. A sentinel test confirms the scan DOES surface them
   (proves the multi-line scan still works if a future change to the
   allow-list accidentally hides them).

Honest deviations
-----------------

- The audit recommended AST-based detection (`@typescript-eslint/parser`
  or `ts.createSourceFile`) as the canonical fix. We chose multi-line
  regex because it lands in this session without a new build dep + AST
  test rig. The multi-line regex has known limitations (cannot detect
  bypasses where options are bound to a variable then passed by name).
  AST migration is tracked as Q2 follow-up per the audit's own
  recommendation.

- 13 pre-existing bypasses surfaced by enabling the scan are deferred
  via `DEFERRED_MEDUSA_MIGRATIONS`. The sentinel test prevents the
  scan from silently degrading.
