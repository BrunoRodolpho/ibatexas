W7-O3 — CLI vs admin endpoint two-person rule reconciliation
==============================================================

Finding (W6 operational drill, Drill 1 §"3am responder using ONLY the CLI"):

  No two-key check on the CLI. Runbook §"Two-key rollout" requires two
  operators. The CLI (this command) writes the Redis flag directly via
  `createKillSwitchStore` — no human confirmation. Only the HTTP admin route
  (apps/api/src/routes/admin/kernel.ts) implements two-step + same-actor
  refusal.

  A 3am responder using ONLY the CLI bypasses the two-person rule entirely.
  The runbook needs to call this out: CLI is for solo emergencies, HTTP is
  for scheduled flips.

Chosen path: (b) — document the CLI as an OPS-EMERGENCY surface with
                   explicit risk acceptance; keep the admin HTTP endpoint
                   as the two-person surface for scheduled flips.

  Rationale: see docs/adjudicate-migration/correctness-remediation/W7-DECISIONS-ops.md §O3.

Implementation:

  packages/cli/src/commands/kernel.ts
    - new `confirmSoloOperatorBypass()` helper that EITHER:
        (i) accepts --yes-i-am-solo-on-call (non-interactive escape hatch)
       (ii) prompts the operator to type "engajar agora" on a TTY
      (iii) refuses with exit code 1 if neither — script pipelines cannot
            single-handedly engage the kill switch by accident.
    - runKillSwitchEnable wired to confirm BEFORE the Redis write.
    - Sentry breadcrumb metadata now carries
        bypass: "two_person_rule"
        surface: "cli"
        bypassMode: "tty_prompt" | "flag"
      so an incident review can correlate CLI-engaged switches with the
      bypass policy.
    - CLI summary line prints `bypass : two_person_rule (surface=cli)`
      so the operator (and any tee'd log) carries the marker forward.

  docs/adjudicate-migration/runbooks/SHADOW-ENFORCE-ROLLOUT.md
    - new §"Two surfaces — different threat models (W7-O3)" subsection
      under Kill-switch procedure naming the explicit posture difference.

  docs/adjudicate-migration/migration/05-kill-switch-strategy.md
    - §"CLI specification" §"Implementation" updated to replace the
      stale M4-era plan ("CLI calls the admin endpoint over HTTPS")
      with the actual current shape + W7-O3 reasoning + the breadcrumb
      tag spec.
