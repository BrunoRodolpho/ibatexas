── Fix summary ──────────────────────────────────────────────────────────────

1. Promoted `stripeAdjudicated` (and its three typed errors:
   StripeAdjudicateRefusedError, StripeAdjudicateDeferredError,
   StripeAdjudicateNeedsReviewError) to the top-level @ibatexas/tools
   barrel at packages/tools/src/index.ts. Previously it was only
   re-exported from the sub-barrel packages/tools/src/stripe/index.ts;
   apps/api routes had no public path to import it. Mirrors the pattern
   already in place for medusaAdjudicated.

2. apps/api/src/routes/stripe-webhook.ts:307-322
   Replaced bare:
     const stripe = getStripe();
     await stripe.paymentIntents.update(paymentIntent.id, {
       metadata: { ...paymentIntent.metadata, medusaOrderId: orderId },
     });
   With wrapped:
     await stripeAdjudicated.paymentIntents.update(
       paymentIntent.id,
       { metadata: { ...paymentIntent.metadata, medusaOrderId: orderId } },
       {
         sourceSubject: `webhook:stripe:${event.id}`,
         idempotencyKey: `${event.id}:metadata-update:${paymentIntent.id}`,
         auditSink: getAuditSink(),
         log: logger,
       },
     );

   The idempotencyKey is namespaced by `:metadata-update:` to keep it
   distinct from the medusa-side cart-complete idempotencyKey (which
   uses bare `event.id`) — both run in the same handler scope so
   distinct keys avoid envelope-hash collision in audit.

3. Extended the catch-branch error filter to also recognise
   StripeAdjudicateRefusedError / StripeAdjudicateDeferredError /
   StripeAdjudicateNeedsReviewError as governance-driven skips (same
   200-to-Stripe posture as the medusa side).
