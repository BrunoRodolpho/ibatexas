── Fix summary ──────────────────────────────────────────────────────────────

1. Shared factory `createTooledOrderService(sourceSubject)` added at
   packages/tools/src/cart/_shared.ts. Wires `adminAdjudicated` to
   `medusaAdjudicated` (the cart-tool kernel shim), namespaces the
   sourceSubject under the calling tool, and does NOT inject an audit
   sink (would require `@ibatexas/llm-provider` import which would
   cycle — same posture as every other cart-tool medusaAdjudicated()
   call site).

2. Migrated 3 callers:
   - packages/tools/src/cart/cancel-order.ts:34
       const svc = createTooledOrderService("tool:cancel_order");
   - packages/tools/src/cart/amend-order.ts:187
       const svc = createTooledOrderService("tool:amend_order");
   - packages/tools/src/cart/check-order-status.ts:18
       const svc = createTooledOrderService("tool:check_order_status");

   Removed dead imports of `createOrderService` and `medusaAdmin`
   from those files.

3. Hard-throw at packages/domain/src/services/order.service.ts:120-130
   replaces the silent fallback. Any future caller that omits
   `adminAdjudicated` and attempts a mutation gets:
     "createOrderService called without adjudicated medusa client —
      refusing to bypass kernel for mutation egress. Construct the
      service via createTooledOrderService() (packages/tools/src/cart/
      _shared.ts) or pass an adminAdjudicated DI per the apps/api/src/
      routes/stripe-webhook.ts wiring example."

   GETs (reads) are unaffected — only mutate() trips the gate, and
   getOrder() flows through fetchAdmin directly.

4. Updated the egress test at packages/domain/src/services/__tests__/
   order-service-egress.test.ts:
   - Flipped the "legacy bare-fetchAdmin path" test to a hard-throw
     assertion (`[W8-V1] cancelOrder THROWS when adminAdjudicated is
     omitted`).
   - GET still fires; POST is NOT issued; throw message matches.
