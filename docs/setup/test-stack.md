# Journey test stack — infra composition + env contract (T1a-11a)

The LLM-driven journey harness (plan-v2 Phase 1a) runs against a **dedicated,
ephemeral** infrastructure stack. This page documents the isolation model, the
env contract, and how addresses are derived. App boot (api + commerce via
`process-compose.test.yaml`) is T1a-11b and documented there.

## Isolation model (binding)

**One composition per run.** Shared-local-infra mode is forbidden — the journey
harness must never point at the dev stack (the T1a-10 fingerprint pre-flight
enforces this at runtime; this page is the operator-side contract). If a shared
mode were ever wanted, the isolation checklist would have to extend to Postgres
DB names, Typesense collections, and NATS subjects — it deliberately does not.

Per run:

```bash
./scripts/gen-env-test.sh                     # once per machine (or --force to rotate)
docker compose --env-file .env.test -f docker-compose.test.yml -p ibx-test-<run-id> up --wait
# ... process-compose test profile + journeys (T1a-11b onward) ...
docker compose --env-file .env.test -f docker-compose.test.yml -p ibx-test-<run-id> down -v
```

`-p ibx-test-<run-id>` gives every run its own containers **and** named volumes
(compose prefixes volumes with the project name). Always end with `down -v`.

## Coexistence with the dev stack

`docker-compose.test.yml` clones the four dev infra services (same pinned
images: `pgvector/pgvector:pg17`, `redis:7-alpine`, `typesense/typesense:27.1`,
`nats:2.11-alpine`) but collides with dev on nothing:

| Axis | Dev (`docker-compose.yml`) | Test (`docker-compose.test.yml`) |
|---|---|---|
| Compose project | `ibatexas` (directory-derived) | `ibx-test` default, `-p ibx-test-<run-id>` per run |
| Container names | pinned `ibatexas-*` | unpinned → `<project>-<service>-1` |
| Named volumes | `ibatexas_*` | `<project>_*`, removed by `down -v` |
| Postgres port | `5433` | `${IBX_TEST_POSTGRES_PORT:-5434}` |
| Redis port | `6379` | `${IBX_TEST_REDIS_PORT:-6380}` |
| Typesense port | `8108` | `${IBX_TEST_TYPESENSE_PORT:-8109}` |
| NATS ports | `4222` / `8222` | `${IBX_TEST_NATS_PORT:-4223}` / `${IBX_TEST_NATS_MONITOR_PORT:-8223}` |

All host ports bind `127.0.0.1`. The test compose interpolation vars are
deliberately **`IBX_TEST_*`-prefixed** (not `POSTGRES_PORT` etc.): docker
compose auto-loads the repo-root `.env` for variable substitution, so reusing
the dev var names would let a dev `.env` drag the test stack onto dev ports.

## Env contract

- **Committed template:** `.env.test.example` — documents every var with the
  rationale inline.
- **Real file:** `.env.test` (gitignored) — generated by
  `./scripts/gen-env-test.sh`. Fresh ≥32-char distinct secrets per generation
  (`JWT_SECRET` ≠ `STAFF_JWT_SECRET` — the server refuses to boot when they
  match), `ANTHROPIC_API_KEY` interpolated from the developer `.env` (never
  committed, never printed), and a unique `IBX_TEST_FINGERPRINT`.

Key points of the contract:

- **Explicit secrets are mandatory.** Under `NODE_ENV=test` a missing secret
  makes `requireSecret()` mint a random per-process value — cross-process auth
  between api, commerce, and the harness silently breaks.
- **`APP_ENV=test` must be injected before process boot** — `rk()` in
  `@ibatexas/tools` captures it at module load.
- **`IBX_TEST_FINGERPRINT` (D-010):** only the test profile sets it; `/health`
  exposes it as `testFingerprint`; the harness pre-flight refuses a stack
  without it. Never add it to dev/prod env files.
- **`ANTHROPIC_MODEL=claude-sonnet-4-6` (D-010):** certifying runs require the
  model to equal the certification target exactly. `ANTHROPIC_MODEL` and
  `EMBEDDING_MODEL_ID` are fail-fast required at claustrum boot (P0-6).
- **Defense-in-depth** on top of the dedicated containers: `REDIS_URL` uses DB
  index `1` (BullMQ's `"ibx"` jobId prefix is hardcoded, not APP_ENV-
  namespaced), and the Postgres database is `ibatexas_test` so accidental
  cross-wiring to the dev stack fails loudly.

## How addresses derive

`infraEndpoints()` in `packages/cli/src/services.ts` (the port source of truth)
already resolves every infra address from env — `DATABASE_URL`, `REDIS_URL`,
`TYPESENSE_HOST`/`TYPESENSE_PORT`, `NATS_URL` — so **no code path hardcodes the
test ports**. A process booted with `.env.test` in its environment (the
process-compose test profile, `ibx svc status`, the harness pre-flight and its
hostname denylist) sees the test-stack addresses; a process without it sees the
dev defaults. `scripts/gen-env-test.sh` keeps the `IBX_TEST_*` compose-
interpolation values and the URL vars in sync from a single set of inputs.

If non-default ports are needed (e.g. two concurrent test stacks), override the
`IBX_TEST_*_PORT` vars in `.env.test` **and** the URL vars together — they are
one contract.
