Symptom
-------
Every `=== "true"` site silently returns false for the common operator
inputs:

  - "TRUE", "True"           → false (case mismatch)
  - "1"                       → false (numeric flag)
  - "yes", "YES", "on"        → false (canonical "yes" flag)
  - " true ", "true\n"        → false (whitespace from .env)

An operator who sets `IBX_AUDIT_POSTGRES_ENABLED=TRUE` in their
production env will get a SILENTLY DISABLED Postgres audit sink. The
runtime gate that the kernel is supposed to enforce stays off until the
operator notices that no audit records are landing in Postgres — which
is hours-to-days later.

Same hazard for `IBX_LEDGER_*` (execution dedup), `NATS_TLS_REQUIRED`
(transport security gate), `STALE_ORDER_DRY_RUN`, `TRUST_PROXY`.

Repro
-----
> process.env.IBX_AUDIT_POSTGRES_ENABLED = "TRUE"
> process.env.IBX_AUDIT_POSTGRES_ENABLED === "true"
< false
> process.env.IBX_AUDIT_POSTGRES_ENABLED = "1"
> process.env.IBX_AUDIT_POSTGRES_ENABLED === "true"
< false

Fix
---
1. New helper: packages/llm-provider/src/parse-bool-env.ts
     export function parseBoolEnv(value: string | undefined,
                                  defaultValue: boolean): boolean
   Accepts (case-insensitive, trimmed):
     "true", "1", "yes", "on"    → true
     "false", "0", "no", "off"   → false
     ""                          → defaultValue
     undefined                   → defaultValue
     any other string            → defaultValue (don't silently flip)

2. Migrate the listed sites to use parseBoolEnv.

Note on the default
-------------------
Each site has its own existing default: some default-false (Postgres
sink, ledger enforce, stale-order dry-run), some default-true
(production NATS_TLS_REQUIRED). The helper takes a defaultValue and the
caller passes the existing default — no behavioural drift for valid
inputs.
