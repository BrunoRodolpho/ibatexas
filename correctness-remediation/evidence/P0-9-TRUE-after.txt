Approach
--------
Added a bootstrap-layer guard that runs BEFORE the existing unknown-token
validation. Distinguishes:

  - Env var UNSET           -> accepted (legitimate empty-set configuration)
  - Env var SET to ""       -> accepted (operator's deliberate empty signal)
  - Env var SET with chars  -> raw stripped to empty kind list AND raw has
                               length > 0 (so it must be commas/whitespace)
                               -> THROWS

This catches the operator-typo case where the env var visibly looks
configured (" , , ", ",", "  ") but parses to nothing. The throw rejects
the bootstrap promise so apps/api/src/index.ts start().catch() routes to
process.exit(1).

Why we don't modify the upstream parseList
------------------------------------------
The parser at @adjudicate/core/kernel/enforce-config.ts is platform code
(shared by all adopters). Some adopters may legitimately want an empty
parsed set with permissive parsing. The bootstrap is the adopter-side
seam to enforce ibatexas-specific safety semantics without forking the
platform.

Tests added
-----------
1. accepts env unset (deliberate empty)
2. accepts an explicitly empty-string env (legitimate empty config)
3. accepts a non-empty enforce list with trailing comma
4. THROWS when IBX_KERNEL_ENFORCE is all commas+whitespace
5. THROWS when IBX_KERNEL_ENFORCE is a single comma
6. THROWS when IBX_KERNEL_ENFORCE is whitespace only
7. THROWS when IBX_KERNEL_SHADOW is all commas+whitespace
8. rejects empty-after-trim BEFORE unknown-token validation in bootstrap
